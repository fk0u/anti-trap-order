## Tujuan dan baseline

**Aktual.** Snapshot telah memiliki halaman Next.js untuk `/lite`, `/soul`, dan `/drill`; Lite menyediakan input skenario/teks, pertanyaan refleksi dan hasil, sedangkan Drill menyimpan progres di `localStorage` ([Lite](../src/app/lite/page.tsx), [Drill](../src/app/drill/page.tsx)). Soul juga mempunyai alur cerita, status lokal dan penyimpanan progres lokal ([Soul](../src/app/soul/page.tsx)). Helper frontend memanggil endpoint Go dengan fallback ke mesin lokal untuk refleksi dan Soul ([API frontend](../src/lib/api.ts), [fallback refleksi](../src/lib/reflect-local.ts), [fallback Soul](../src/lib/soul-local.ts)). Backend Go telah menyediakan endpoint health, skenario, reflect, daftar arc dan soul-step ([handler](../internal/handler/handler.go)); middleware rate limit, batas ukuran request, CORS, header keamanan, pemulihan panic, serta timeout HTTP dirangkai di entrypoint ([server](../cmd/server/main.go), [middleware](../internal/middleware/middleware.go)). Ada validator skenario/graf cerita dan sejumlah unit test engine ([validator](../scripts/validate-data.ts), [test reflect](../internal/reflect/engine_test.go), [test Soul](../internal/soul/engine_test.go)). Keberadaan kode uji bukan bukti bahwa tes telah dijalankan atau lulus.

**Gap yang menjadi titik awal.** Kontrak API menghendaki kesesuaian tipe Go/TypeScript, tetapi kode frontend lokal dan Go tidak identik dalam beberapa cara pemeringkatan hasil; jalur penyelesaian arc lokal juga perlu dibuktikan sama dengan Go ([engine Go](../internal/reflect/engine.go), [engine Soul](../internal/soul/engine.go), [fallback lokal](../src/lib/reflect-local.ts), [kontrak terdokumentasi](../docs/api-contract.md)). Validator data belum membuktikan kesesuaian dua dataset client/server atau keseluruhan request/response. README menyebut fase landing page lama yang belum selesai, sedangkan snapshot berisi alur produk tambahan; README tidak cukup untuk menilai status semua fitur ([README](../README.md)). Outline menyebut Action Card dengan kanal pelaporan dan Soul dengan rangkaian misi/karakter; cakupan tersebut tidak boleh dianggap terpenuhi tanpa verifikasi produk dan kode. Infrastruktur produksi, telemetri, database, autentikasi, uji aksesibilitas, serta rollback teruji tidak dibuktikan oleh snapshot.

## Milestone usulan

Urutan di bawah bersifat **Usulan**; tiap fase bergantung pada persetujuan ruang lingkup fase sebelumnya. Peran bersifat fungsi yang dapat dirangkap, bukan penugasan kepada orang tertentu.

| Fase dan dependensi | Pekerjaan, peran usulan, dan keluaran | Kriteria keluar dan keterlacakan |
|---|---|---|
| **M0 — Tetapkan penerimaan & inventaris** (mulai; prasyarat semua fase) | Pemilik produk bersama engineer frontend/backend menginventarisasi alur yang ada, tautan antara requirement, route, kontrak, dataset dan test; menetapkan perilaku yang harus sama saat API tersedia/tidak tersedia, batas privasi teks bebas, batas dukungan browser dan keputusan konten. Keluaran: daftar gap terprioritas dan kriteria penerimaan per alur. | **PRD-01–PRD-05** masing-masing ditandai ada/parsial/belum dibuktikan; kontrak teknis dan keputusan terbuka terdokumentasi. Telusuri [PRD](PRD.md), [TRD](TRD.md), [AFD](AFD.md), [DBD](DBD.md), [BSD](BSD.md). Outline produk adalah konteks, bukan bukti implementasi. |
| **M1 — Kontrak, data dan parity** (M0) | Engineer backend/frontend dan pemilik konten menyepakati satu kontrak berversi atau sumber tipe/fixture bersama; audit identifier, enum, field wajib/opsional, karakter Unicode, ukuran input, nilai state dan format error. Perluas validator untuk kedua kumpulan data, ID unik/rujukan valid, cakupan endpoint serta lintasan fallback. Buat fixture kasus sama untuk membandingkan hasil Go dan lokal; perbaiki perbedaan hasil reflect dan akhir Soul yang ditemukan. Keluaran: kontrak/fixture dan pemeriksaan otomatis. | Input valid menghasilkan keluaran semantik yang disepakati di kedua jalur; input salah ditolak konsisten; kegagalan validator memblokir merge. Keterlacakan utama: **PRD-01** (input/ID/batas), **PRD-02** (jawaban refleksi), **PRD-03** (hasil/fallback), dan **PRD-04** (alur Soul). Tidak mengharuskan algoritme sama bila keputusan produk menyatakan perbedaan yang disengaja. Jejak ke TRD, AFD, DBD, BSD. |
| **M2 — Keamanan input dan privasi** (M1) | Backend engineer dan reviewer keamanan/privasi meninjau dekode JSON, batas teks, request body, validasi ID/answers/state, pesan error dan kebijakan log; tambahkan tes batas ukuran, JSON rusak, field berlebih, ID tak dikenal, input Unicode dan percobaan payload besar. Perjelas pada UI bahwa teks bebas dikirim ke backend bila endpoint digunakan, atau ubah rancangan agar pemrosesan lokal saja. | **PRD-01** dan **PRD-03** menjadi fokus privasi input, penanganan teks, dan informasi hasil/fallback. Kriteria keluar yang diusulkan: uji keamanan/privasi menunjukkan input invalid tertangani aman, limit berfungsi, dan teks pengguna tidak dicatat oleh komponen yang diaudit; konfigurasi origin/forwarded header ditetapkan untuk lingkungan yang dipilih. Tidak menambahkan autentikasi, database, atau telemetri tanpa keputusan. Jejak ke TRD, AFD, DBD, BSD. |
| **M3 — UX, aksesibilitas dan degradasi** (M1; M2 untuk perubahan input) | Engineer frontend dan reviewer aksesibilitas menguji alur Lite/Soul/Drill memakai keyboard, pembaca layar, zoom, kontras dan viewport mobile; tambah label/fokus/indikasi error, loading, kosong, timeout, kegagalan clipboard/storage/audio, serta kontrol pengulangan. Uji disclaimer dan Action Card sesuai scope yang disetujui. | Keterlacakan utama: **PRD-02–PRD-04** untuk alur, hasil, Soul dan degradasi; **PRD-05** untuk navigasi dan aksesibilitas. Tiap alur inti selesai tanpa mouse; status gagal dapat dipahami dan tidak membuang progres tanpa penjelasan; fallback memenuhi acceptance fixtures M1. Perbaikan tidak boleh menjanjikan deteksi pasti. Jejak ke AFD dan BSD. |
| **M4 — Gerbang rilis dan pemulihan** (M1–M3) | QA menjalankan build, lint dan seluruh uji Go/TypeScript/data pada CI; SRE/engineer rilis mendokumentasikan environment, health-check, konfigurasi origin, artefak/versi dan prosedur pemulihan. `scripts/deploy.sh` saat ini melakukan `git push`, `rsync --delete`, build/test lalu reload PM2; jangan menjalankannya sebelum mekanisme push, kredensial, target, backup/rollback dan persetujuan eksplisit dirancang ulang. Promosi produksi memerlukan otorisasi operator; jangan klaim URL live atau deployment berhasil tanpa bukti. Jejak ke TRD, BSD dan PRD. |

## Prioritas risiko dan keputusan terbuka

Urutan risiko usulan: **P0** hasil berbeda saat backend gagal (dapat mengubah saran pengguna); **P0** input bebas/konfigurasi proxy dan log berpotensi memperluas paparan; **P1** data skenario/arc berbeda atau rujukan rusak; **P1** deployment berpotensi melakukan push dan penghapusan sinkronisasi tanpa rollback yang terdokumentasi; **P2** aksesibilitas dan kegagalan storage/clipboard/audio belum dibuktikan. P0 harus menjadi gerbang sebelum rilis publik; prioritas final perlu persetujuan pemilik produk/keamanan.

**Perlu keputusan:** apakah produk memproses teks bebas di server atau lokal; algoritme mana yang menjadi sumber perilaku kanonis; apakah kanal pelaporan lokal, fitur berbagi, karakter custom dan multi-misi Soul termasuk target rilis; browser/tingkat aksesibilitas yang didukung; lingkungan serta pemilik persetujuan deployment; kebutuhan observabilitas yang tidak menangkap isi pesan. Usulan observabilitas minimal adalah metrik agregat kesehatan/error, latensi dan fallback tanpa body, teks bebas, identifier persisten atau data personal; aktifkan hanya setelah tinjauan privasi. Tidak ada estimasi tanggal karena kapasitas, pemilik, dan definisi scope belum ditetapkan.
